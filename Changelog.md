# Changelog

## 2026-07-19 — Возрождение проекта
Проект был взят из состояния "не начато" в штабе Core_operation_all_project. CLI падал на Windows, а документированный режим командной строки был фиктивным.

**Найдено и исправлено:**
1. **Крах на старте на Windows** — `cleaner.py`, `text_cleaner.py`, `ai_tools.py` печатали эмодзи/спецсимволы (✓, ℹ, →) в stdout, а консоль Windows в cp1251 их кодировать не может → `UnicodeEncodeError`. Исправлено принудительным `reconfigure(encoding="utf-8")` для stdout/stderr во всех трёх точках входа.
2. **CLI-режим с аргументами не был реализован** — `cli_mode()` в `cleaner.py` собирал аргументы через `argparse`, но код их выполнения был буквально заглушкой-комментарием («здесь будет код выполнения команд из старой версии»). Любая команда (`clean`, `detect`, `patterns`, `watermark-*`) молча игнорировалась, печаталось «CLI режим временно недоступен» — то есть вся секция README «⌨️ Командная строка» не работала. Реализована функция `run_cli_command()`, которая связывает все 6 подкоманд с той же логикой, что уже использует интерактивное меню.
3. **Слияние с параллельным фиксом** — пока чинил CLI, обнаружился более ранний коммит `3df75fa` на той же ветке (`Fix .docx file support...`), не подтянутый локально. Смёржил без конфликтов: тот фикс чинил чтение .docx в интерактивных функциях детектора/водяных знаков (раньше падало с `UnicodeDecodeError`, так как .docx — это ZIP+XML, а не plain text).

**Проверено живым запуском:** все 6 CLI-подкоманд (clean, detect, patterns, watermark-add/check/remove — включая полный цикл add→check→remove с побайтово идентичным результатом), интерактивное меню, оба legacy-скрипта (`text_cleaner.py`, `ai_tools.py`).
